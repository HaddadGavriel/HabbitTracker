# Read-only mobile Today walkthrough

Use an Android development client with an onboarded test account and a backend approved for manual testing. Device checks have not been run in this workspace. Automated tests mock Auth, API, navigation and app lifecycle; they never use live data.

1. Sign in and open **Home → Today**. Expect a loading indicator, then the server's local date and timezone. Compare the cards with that account's `GET /today` response: names/types come from each occurrence's snapshot, target cards show progress/target and an optional unit, and all returned rows remain in server order. An archived habit's retained occurrence must still appear when returned. There are no completion or editing controls.
2. Using controlled test responses, check **In progress**, **Completed**, **Missed**, **Excuse pending** and **Excused**, including progress above target and a target without a unit. Changing the device clock/timezone must not reinterpret the returned date, schedule or status. A successful empty response shows its date/timezone and **No habits to show for this date.**
3. Simulate an initial offline/401/5xx/timeout failure. Expect a readable error and **Retry loading**, with no invented date or empty-success message. Restore the connection and retry. Pull down on a loaded list (including an empty list): expect the refresh indicator and an updated server response.
4. Load a dated response, then simulate a failed refresh across local midnight. The old date, timezone and cards must remain together with **Showing the last loaded date and habits.** A successful retry replaces the date and rows together; an empty result removes the old rows.
5. Return Home and reopen Today: expect a fresh read. Background and foreground the app while Today is visible: expect another read, including across midnight. Repeat while Home is visible: Today must not fetch in the background. Check Android Back, scrolling/pull-to-refresh and screen-reader labels on device.
6. With delayed mocked responses, leave/reopen Today, sign out, switch accounts and renew the same account's token. Leaving or changing accounts must clear the previous date, rows and errors. Late successes and failures must not repopulate them or overwrite a newer result. Token renewal keeps already-loaded data while reading with the new credentials.

From `mobile/`, run `npm test` and `npm run typecheck`. Focused tests in `tests/api.test.cjs` and `tests/today.test.cjs` cover the GET contract, displayed states, loading/empty/error/retry, date retention, focus/foreground refresh, route protection and stale responses. The client only reads `GET /today`; the existing backend owns occurrence generation/reconciliation and states. No backend or migration changes are needed.

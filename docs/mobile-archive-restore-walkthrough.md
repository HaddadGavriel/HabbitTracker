# Mobile archive and restore walkthrough

Use an Android development client and an onboarded test account with active and archived habits on a backend approved for manual testing. These device checks have not been run in this workspace. Automated tests use mocked Auth/API and never modify live data.

1. Open **Home → My habits**. Expect **Active** selected. Switch to **Archived**, then back: each filter loads its own server list, with loading, empty and retry states. Active cards open the editor; archived cards offer **Restore** without editable fields.
2. Open an active habit, change its name without saving, and tap **Archive habit**. Read the explanation that history and already-created obligations, deadlines and progress remain, plus the warning that unsaved edits will be discarded. Cancel and verify the draft remains and no archive request occurs. Confirm instead: expect one archive request, a return to My habits, and a refreshed Active list without the habit. Find it under Archived with its last saved configuration.
3. Restore an archived habit. Cancel once, then confirm. Expect one restore request and a refreshed Archived list without the habit. Switch to Active and open it to verify its saved configuration is editable again. An archived habit opened through an old editor link must remain uneditable and explain where to restore it.
4. With mocked delays, double-tap confirmation and verify only one mutation occurs. During Save changes, Archive must be disabled; during archive confirmation or an archive request, fields and Save must be disabled. A same-account token refresh must retain mutation guards. Smoke-check normal creation and editing.
5. Simulate a definite failure (401/422) and verify a readable error and an explicit retry path. Simulate a timeout/lost response/5xx: the message must explain possible success and offer **Refresh current server state**. Refresh performs a read, never repeats the mutation. In the editor, read the warning that refresh replaces unsaved edits; a failed read preserves the draft and uncertainty. If the archive succeeded, editing is blocked; otherwise the current configuration loads. For restore, refresh Archived before deciding whether another restore is needed. A failed post-success list refresh must offer a list retry without repeating the confirmed mutation.
6. During mocked pending reads and mutations, switch filters, leave the screen, switch accounts or sign out. Previous habits, confirmations and errors must clear, and late results must not repopulate the current screen, navigate for another account or refresh the wrong filter. Reopen to read fresh data. Check Android Back, keyboard scrolling and accessibility labels on device.

From `mobile/`, run `npm test` and `npm run typecheck`. Focused mocked coverage includes lifecycle API contracts, filters, confirmation/cancellation, refresh after success, failure/timeout recovery, duplicate requests and stale responses. No backend changes or migrations are needed.

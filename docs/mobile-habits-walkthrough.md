# My habits: read-only mobile walkthrough

Run this checkout in an Android development client with the public settings in `mobile/.env.example` and the existing backend. This change needs no backend release or migration. Use two existing, onboarded test accounts: one with no active habits, and one that already has habits. Do not create, edit, archive, or complete habits for this walkthrough.

1. Sign in to the empty account. From **Home**, open **My habits**. Verify a loading indicator precedes **No active habits yet.** Pull down even on this short list; the refresh indicator should finish and the empty state should remain.
2. Return Home, sign out, and sign in to the existing account with habits. Open **My habits**. Compare names with that account's existing records. Only active habits should appear. Binary habits show **Binary (yes/no)**; target habits show the amount and the unit when present. Daily schedules say **Every day**; selected schedules show weekday names, with ISO day 1 = Monday and 7 = Sunday. Schedules describe the owner's configured weekdays, without timezone conversion.
3. Pull down to refresh the populated list. It should remain visible while loading. With the API temporarily unreachable, refresh again: verify a readable error, **Showing your last loaded habits.**, and **Retry**. Restore connectivity and retry. Repeat while opening the screen for the first time: an initial failure must show an error/retry instead of the empty state.
4. With a slow habits request pending, return Home and sign out. Press Android Back and try a `/my-habits` deep link while signed out: the habits screen must stay protected. Sign in as the other account; previous names and errors must never appear. Repeat with an expired/refreshed session and verify subsequent reads use the current session.
5. Return Home and verify the identity and **Infrastructure diagnostics** entry still work. Do not register a device or run the infrastructure test as part of this read-only walkthrough. Existing authentication/onboarding checks remain in [the auth walkthrough](mobile-auth-walkthrough.md).

Automated tests mock the API and session lifecycle, including empty/error results, active-only filtering, retry, refresh, overlapping requests, account changes, and unmounting. Run `npm test` and `npm run typecheck` in `mobile/`. These tests do not claim native rendering, pull gestures, Android Back/history, or real-account verification. No configured account credentials, mobile `.env`, or Android device were available in the implementation workspace, so the device steps above remain to be run with the existing test accounts; no live data was changed.
